### Fixed

- Preserve an existing destination when a shell file move fails before committing its replacement, and protect a Git lock acquired by another operation after publication.
- Keep both entries and report an error when plain `mv` would replace a regular file with a symlink or FIFO, or the reverse. `mv --backup` can save the existing destination before moving the other type into place.
- Keep an existing `mv --backup` file if preparing its replacement fails. If installing the source fails, try to restore the saved destination when its name remains free. Keep the backup if a new entry occupies the destination.
- Protect files created after `mv -n`, `mv -i`, `mv --update=none`, or `mv --backup` checks that the destination is free, and preserve a replacement file that appears after an interactive overwrite is confirmed.
