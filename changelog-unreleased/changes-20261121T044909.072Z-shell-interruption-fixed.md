### Fixed

- A single stop request interrupts the running shell command, including commands that ignore `SIGINT`. If the worker cannot respond, a forced stop resets the shell session.
- Allow an interrupted shell command's in-progress file saves time to finish before forcing a Worker reset.
- Resume terminal input as soon as a command finishes. Bound queued output when the terminal or tool is slow to receive it.
- Preserve existing files when Stop interrupts shell redirection before truncation begins.
- Stop interrupts the shell while it is waiting for a background job. With no operands, `wait` returns success once it has collected the jobs.
- Deliver subsequent group signals to shells that ignored a previous signal. A direct `SIGTERM` that terminates the waiting shell ends `wait` promptly while the background child continues.
- Stop interrupts scripts waiting for input from a named pipe and commands waiting for their implementation to load.
- Closing one shell input descriptor preserves buffered data for other descriptors that share the stream. Long shell streams release completed I/O notifications as they finish.
- Report errors when closing shell command files while preserving any earlier failure or signal exit status.
- When shell commands respond to Stop, discard staged output that has not started saving and clean up temporary `sed -i` files and unfinished Git locks.
