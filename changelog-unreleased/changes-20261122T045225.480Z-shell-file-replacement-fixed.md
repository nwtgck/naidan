### Fixed

- Finish an accepted backed-up `sed -i` replacement after Stop, and preserve recoverable files when a replacement cannot be confirmed.
- Preserve existing files when `patch` stops before publishing a replacement or `git apply` fails while preparing patched contents, including file type changes.
- Preserve unrelated files when a `patch` deletion, rename, backup, or explicit output encounters a different file at the expected path.
- Report a conflict before writing when `patch` would send rejected hunks and patched output to the same file.
- Keep competing files when `cp` detects that the destination changed after its overwrite decision. `cp -b` reports an error and preserves both entries when it would need to replace a regular file with a symbolic link or special entry at the backup path, or the other way around.
- Report a conflict when `cp -b` cannot verify that the source and previous backup are separate files. When `cp -u` writes through a symbolic link, compare the modification time of the file it would update.
- Make `git apply --index` stop before changing worktree files when another operation holds the index lock, and preserve the existing index if it cannot be read.
- Preserve competing Git branch references, reject commits whose parent reference changed, and finish accepted reference and reflog updates after Stop.
- Finish accepted stash removals after Stop, keep recovery history available after a failed update, and preserve the remaining stash entries if the list changes during `git stash pop`.
- Keep the original branch until its new name and any HEAD update are in place, and finish accepted branch renames after Stop.
