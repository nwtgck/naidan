# HizoFS V1 format tests

This directory owns black-box tests that protect the released-data meaning of HizoFS V1 without freezing implementation choices that V1 deliberately leaves free.

The primary checks are:

- frozen historical V1 containers must still reopen through a fresh HizoFS runtime;
- declarative high-level operation histories are applied both to real HizoFS and to a small persistence-agnostic reference model;
- after persistence and a fresh reopen, the complete observable filesystem state must exactly match the reference model, including the absence of unexpected extra entries;
- exact byte assertions belong here only when the V1 format authority makes the representation uniquely determined.

These tests intentionally do **not** freeze write-call counts, write chunk sizes, buffering, batching, cache policy, physical I/O sequence, allocation strategy, or Segment packing choices unless the V1 format or durability contract explicitly makes one of those choices normative.

The exact-anchor suite also deliberately distinguishes compatibility bounds from tunable writer/runtime policy even when both currently live beside V1 format constants. In particular, the current PBKDF2 writer default, random-identity retry count, and Naidan path-expansion/symlink-follow safety limits are explicitly reviewed but not exact-value anchors. Changing them still requires normal correctness/security review, but is not automatically classified as a V1 persisted-format break. Reader-acceptance bounds and values that can make existing V1 bytes unreadable remain exact anchors.

The frozen fixture corpus is historical input, not a snapshot that should be regenerated whenever the current writer changes. A new legal V1 representation may be added as another historical fixture; existing fixtures should not be rewritten merely to follow writer implementation changes. `fixtures/manifest.json` registers every historical fixture and its reviewed file hash so accidental fixture replacement is visible immediately.

`v1-format-test-matrix.ts` is the audit ledger for this test owner. It classifies each major area as covered, blocked by the current public composition surface, still remaining, or intentionally unfrozen, and its companion test requires every evidence path to exist. The ledger is test-planning authority only: adding a row never turns an implementation detail into a V1 persisted-format contract.

Current coverage includes:
- positive historical fixtures are required to declare `real_hizofs_writer` provenance so hand-authored data cannot silently enter the compatibility corpus;
  This is a reviewed freeze-time provenance attestation, not a regeneration contract: normal tests must not recreate these fixtures with the current writer or require current writer physical bytes to remain identical.

- frozen empty-container, zero-byte-file/truncate-to-zero, and representative real V1 containers;
- frozen sparse/reflink, symlink, Unicode-path/content, NFC/NFD-distinct namespace, maximum lexical-boundary, credential-replacement, multiple-active-Credential-Slot, complex mutation-history, tree-backed-directory/large-file, 600,000-byte large-file, and true multi-chunk-file containers generated through the real HizoFS writer and then retained as historical reader inputs;
- declarative create-file/write/write-at/truncate/move/remove/symlink/whole-file-reflink operations, including idempotent ensure semantics, `keepExistingData: false` replacement/truncation, single-active-writer enforcement, truncate-growth zero filling, file/symlink and empty-directory replacement matrices, identical-path move semantics, directory-cycle rejection, prepared-write abort isolation, and rejection paths that preserve the pre-existing observable state;
- full observable-tree comparison after a fresh read-only reopen, including Unicode names/content and maximum legal filename/symlink-target boundaries;
- Copy-on-Write isolation after reflink mutation, including mutation of a frozen historical reflink after a fresh reopen;
- sparse-hole semantics after reopen;
- real writer scenarios that cross the 4 KiB inline-directory/inline-file boundaries, retain the earlier 600,000-byte large-file corpus case, and persist a 1,100,000-byte file that exceeds the 1,048,576-byte V1 File Data plaintext limit while asserting only the resulting observable state, not the chosen physical packing;
- `sync()` followed by simulated crash/recovery and another fresh reopen;
- credential replacement followed by rejection of the old passphrase and fresh reopen with the replacement passphrase, invalid replacement rejection that preserves the old authority and filesystem state, successful replacement surviving an immediate simulated crash after acknowledgement, a dynamic fault campaign over every currently observed credential-publication file-durability transition, exact passphrase UTF-8 profile boundaries including every forbidden line separator, plus frozen multiple-active-Credential-Slot bytes that reopen through either passphrase and retain both slots across a normal current-writer filesystem mutation;
- exact V1 anchors for format identity, identifier lexical forms, record-kind/tag/flag values, path/shard binding, persisted lexical encodings and rejection of non-canonical forms, full primary framing sizes, Superblock plaintext and passphrase-credential parameter layouts, Segment Footer framing, canonical Unlock Envelope JSON including bounded opaque unknown credential methods and the 32-Slot acceptance limit, crypto context/AAD framing, big-endian scalars, Record Reference field order, canonical Directory ordering, and representative persisted page/record payload vectors;
- frozen legal-variant V1 containers for single-copy Superblock and Unlock Envelope corruption/missing-copy degradation, plus authenticated active-Commit corruption and active-Commit-Segment-missing cases that fall back to the previous Commit, proving recovery still exposes the complete V1-defined state;
- frozen negative V1 containers for dual-Superblock corruption/missing-copy loss, dual-Superblock truncation below the mandatory header size, dual-Unlock-Envelope corruption/missing-copy loss, Segment corruption, complete referenced-Segment absence, Segment physical-path/content misbinding, and a correctly authenticated authority requiring unsupported feature semantics, with manifest hashes;
- authenticated same-sequence Superblock and Unlock Envelope conflict tests that must fail closed rather than choose one authority arbitrarily, an authenticated Superblock rollback-floor test that rejects older Unlock Envelope authority, and a credential-authority rollback test proving that a credential removed from the newest authenticated Unlock Envelope cannot be resurrected from an older generation;
- systematic crash/fault campaigns for file-content overwrite, standalone file creation, namespace move, and recursive-delete mutations that discover the current writer's persistence checkpoints at runtime and reinject faults at each discovered point without asserting their count or order;
- normal current-writer updates of frozen representative, tree-backed, multi-chunk, reflink, credential-replaced, NFC/NFD-distinct, and complex mutation-history V1 containers, proving read-modify-write compatibility without comparing the resulting physical container image;
- corpus-coverage gates that require every positive, legal-variant, and negative manifest entry to have a corresponding active reader test case rather than merely existing on disk with a valid hash;
- read-only application-session semantics that reject namespace and file mutations against frozen V1 bytes while leaving the complete persisted state unchanged;
- session lifecycle semantics that invalidate already-acquired handles after close, automatically abort an uncommitted writable so staged bytes cannot leak into persisted state, and let a fresh session observe the same complete historical state, plus opened-readable generation stability across a later published file replacement;
- real directory-iterator generation semantics across the 128-entry paging boundary: an iterator remains on the generation captured when iteration starts, while a later iterator and fresh reopen observe a subsequently published mutation.
- real application read-snapshot semantics: a captured read snapshot remains pinned to its published generation while the writable session advances, rejects mutation, becomes unusable after close, and does not prevent a later fresh reopen from observing the advanced persisted state.

Fixture-export helpers exist only to support an explicit reviewed fixture-creation step. Normal reader and writer tests do not regenerate historical fixtures. Existing frozen fixtures should remain unchanged when the writer later adopts another legal V1 physical representation.

Persisted snapshot/subvolume lifecycle, container-local Credential Slot add/remove lifecycle, and any newly discovered V1 decision point not already represented by these anchors/corpora remain future coverage. Credential replacement, crash-after-acknowledgement recovery, dynamic fault injection across every currently observed credential-publication file-durability transition, multiple simultaneously active slots, and fail-closed selection when the newest authenticated credential authority has removed the passphrase used by an older generation are covered. Lower authenticated-store tests continue to own finer coordinator-internal degraded/resolution state-machine detail; the V1 black-box campaign stays at durability transitions visible through the application-level replacement operation rather than duplicating every non-durable physical checkpoint. The current application-level management surface also does not expose add/remove operations, so the suite freezes the observable rollback protection without pretending that the add/remove lifecycle itself is covered. Explicit-bulk commit/abort lifecycle is intentionally outside this persisted-format owner: the operation batches ordinary namespace mutations rather than defining a distinct V1 representation, and its transactional runtime behavior remains owned by the application/filesystem tests. This suite continues to verify that the resulting ordinary namespace/file states remain readable as V1 without freezing the batching mechanism itself. Persisted snapshot/subvolume coverage should stay at the high-level observable surface; the current application-level session does not expose topology-aware subvolume mounting, so these tests must not descend into internal planners merely to claim coverage. The unsupported-required-feature corpus case is intentionally a correctly authenticated V1 container rather than byte corruption, so the reader proves that unsupported semantics fail closed rather than accidentally entering corruption fallback. Degraded one-copy fixtures are reader/recovery compatibility inputs only: the current application-level writable composition explicitly requires converged Superblock copies, so these tests do not bypass that safety gate merely to assert writable recovery from a degraded authority. Future additions must continue to test V1-observable guarantees rather than preserve incidental physical operation counts or ordering.
