# Marking upstream fixes

- Mark each logical Naidan modification to upstream-derived code with an adjacent English comment starting with `// Naidan fix:`. Explain the reason or failure being prevented, not merely what the code does.
- For transformations defined in `replacements.ts`, put the comment in the replacement (`after`) code so it accompanies the fix in the transformed source. Keep `before` text and reviewed original input identities unchanged. A deletion belonging to an adjacent commented fix does not need a separate marker.
- Use `String.raw` literals for source fragments so upstream backslashes and real line breaks stay readable. Place delimiters at the exact fragment boundaries; do not add a leading line-continuation backslash, trim whitespace, or normalize newlines. Backticks and `${...}` inside a future fragment require explicit review. Keep exact input/output hash checks intact.
- Use the same prefix when directly modifying an upstream-derived file. Keep its original baseline and the local changes distinguishable; the name `upstream/` alone does not require every future file there to be unmodified.
- Preserve upstream formatting, naming, signatures, and code structure wherever unrelated to the fix. Whole-file lint exemptions are allowed for upstream-derived files to avoid style-only churn; Naidan-owned integration code and tests remain normally linted.
- A short prefixed comment is sufficient. Do not introduce additional source copies or directory layers solely to mark modifications. See `README.md` for provenance, verification, and removal requirements.
- Read unmodified source from the pinned installed dependency after verifying its recorded hash; do not save redundant original code copies. Extract reviewed browser sections without whitespace normalization and retain their independent hashes. Keep original-failure and transformed-consumer tests distinct, and preserve existing license notices. A future locally modified upstream-derived file remains allowed when its original baseline and changes are distinguishable.
